# Оповещения Плюс — Backend

Виджет amoCRM для отправки уведомлений в Telegram и MAX. Уведомление настраивается как действие в цифровой воронке (в перспективе — и в конструкторе salesbot) и запускается по событиям сделки: с текстом, подставляемыми данными сделки, кнопками (ссылка или запуск salesbot-сценария) и записью ID сообщения в поле сделки.

## Возможности

- **Боты.** Подключение ботов Telegram/MAX двух типов: «свой» (привязан к одному аккаунту) и «общий» (один бот обслуживает несколько аккаунтов amoCRM через команды в чате). Лимиты: не более одного общего бота на канал и не более 10 ботов на аккаунт.
- **Общий бот** — команды `/connect`, `/disconnect`, `/accounts` для привязки amoCRM-аккаунта к чату; в группах доступны только администратору группы.
- **Чаты** — синхронизация списка чатов, в которые добавлен бот, привязка чата к конкретному аккаунту.
- **Триггер «Отправить уведомление»** — настройка бота, чата (из списка или по ID из поля сделки), текста с подстановкой данных сделки, формата разметки (Markdown / HTML / без разметки) и до 20 кнопок.
- **Кнопки** — «Ссылка» (с подстановкой данных сделки в URL) или «Запустить salesbot»; настраиваемое действие после нажатия (ничего не делать / удалить кнопку / удалить все кнопки).
- **Доставка** — деление длинных сообщений на части, до 4 повторных попыток при временных сбоях API с паузами 10 сек / 60 сек / 5 мин.
- **Журнал уведомлений** — история отправок с попытками и техническими деталями ошибок, автоматическая очистка записей старше 14 дней.

## Стек

- PHP 8.2+, Laravel 12
- MySQL (продакшен) / SQLite (разработка)
- Очереди Laravel — асинхронная отправка уведомлений и обработка вебхуков

## Установка

```bash
git clone <repository-url>
cd notifies
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate
```

> Часть зависимостей проекта распространяется через приватный Composer-репозиторий. Для установки потребуется файл `auth.json` с доступом к нему — обратитесь к ответственному за инфраструктуру проекта.

## Переменные окружения

Помимо стандартных Laravel-переменных (`DB_*`, `QUEUE_CONNECTION` и т.д.), для работы ботов нужны:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
| `TELEGRAM_WEBHOOK_URL` | URL, на который Telegram присылает вебхуки |
| `TELEGRAM_CERTIFICATE_PATH` | Путь к сертификату (если используется self-signed) |
| `MAX_BOT_TOKEN` | Токен бота MAX |
| `MAX_WEBHOOK_URL` | URL, на который MAX присылает вебхуки |
| `MAX_CERTIFICATE_PATH` | Путь к сертификату (если используется self-signed) |

## Запуск

Помимо веб-сервера, для полноценной работы нужны:

```bash
php artisan queue:work      # отправка уведомлений и обработка входящих вебхуков — асинхронные
php artisan schedule:work   # плановые задачи (очистка журнала, проверка вебхуков ботов)
```

Плановые задачи (`routes/console.php`):
- ежедневная очистка записей журнала старше 14 дней;
- проверка состояния вебхуков ботов каждые 6 часов.

## Структура проекта

```
app/
├── Http/Controllers/V0/           # API виджета: боты, чаты, триггеры
├── Http/Controllers/V0/Webhook/   # входящие вебхуки Telegram/MAX
├── Http/Controllers/V1/           # активация виджета, справочники (маски)
├── Jobs/                          # асинхронная отправка уведомлений
├── Notifications/                 # сборка и отправка сообщений по каналам
├── Services/                      # вспомогательная логика (идемпотентность, обработка ошибок, callback-и)
├── Models/                        # аккаунты, боты, чаты, триггеры, журнал
└── Analytics/Panels/              # панель журнала уведомлений
```
